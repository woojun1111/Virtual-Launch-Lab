# Repository integration review — 2026-11-22

Scope: current web entry, controls, rendering modules, physics interface, training/export entrypoints, repository layout and regression checks. This is not a validation of a real vehicle or learned-policy performance.

## Changes

- Added keyboard manual actions without changing the existing Euler integration and terminal conditions. Manual input bypasses ONNX, permits engine cutoff, clamps actuator limits and handles empty fuel.
- Serialized mode switching with pending inference; missing models leave the current mode selected and pause playback. Reset during loading cannot resume a replaced episode.
- Preserved timeout versus crash distinction and nonzero impact velocity in HUD/state.
- Added bounded nozzle trajectory, ballistic-reference marker and pooled smoke. These visualization modules never write to physics state.
- Fixed CommonJS legacy-test loading after the root package became ESM (`dist/package.json`).
- Removed the obsolete slider controller; moved historical README material to `docs/legacy-experiments.md` and documented the two distinct Python environments.
- Load ONNX Runtime on demand when AI is requested, rather than as part of manual startup.

## Verification

- 11 web module tests passed.
- All 12 legacy CJS test scripts passed. Their printed training/replay scores refer to legacy toy/saved-data experiments, not current PPO performance.
- 11 existing Python unit tests passed.
- New `rl-pipeline` environment passed the Gymnasium checker (unbounded observation range warnings are expected).
- For 20 identical input-action steps, Python and JS state/reward agreed within absolute tolerance 1e-10. This checks the dynamics path, not ONNX output parity or all initial conditions.
- Vite production build passed.

## Remaining limitations

No trained ONNX model is included; AI inference and successful autonomous landing were not end-to-end tested. No browser/GPU interaction test was available in this environment. Smoke is a visual approximation, grid fins do not apply forces, and the new app starts in descent rather than implementing a complete launch/separation/recovery mission.
